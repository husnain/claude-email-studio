# Skills I Chose

## Use these

**For writing campaigns: `coreyhaines31/marketingskills`**

The GitHub repo (github.com/coreyhaines31/marketingskills) has 58,501 stars, which is an unusually strong signal for a skills repository. Install counts back this up: the `@cold-email` skill has 133K installs, `@emails` has 83.5K, and `@email-sequence` has 55.1K. The repo description ("Marketing skills for Claude Code and AI agents. CRO, copywriting, SEO, analytics, and growth engineering.") is scoped and credible, not hyperbolic. This is the clearest choice for drafting campaign copy and nurture sequences.

**For sending email: `resend/resend-skills` and `resend/react-email`**

Both repos are published by the `resend` GitHub organization, which is the company that makes the Resend email API. The `react-email` repo has 19,910 stars, confirming this is a real, active company. Their sending skills (`resend/resend-skills@resend` with 24.2K installs, `resend/react-email@react-email` with 9.9K installs) and their `resend/email-best-practices@email-best-practices` skill (8.2K installs) are written by people who built the actual sending infrastructure, so the advice is authoritative and the API integration will be accurate.

## Avoid these

**`cosmoblk/email-marketing-bible@email-marketing-bible`**

The description claims "88K words, 908 sources, 19 industry playbooks" — the kind of marketing language that belongs on a landing page, not a skills file. The numbers don't hold up: only 362 GitHub stars and 424 installs from an anonymous individual with no other verifiable track record. The gap between the bold claims and the low adoption is a red flag.

**`resend.com@Resend`**

This one uses a domain-style publisher name (`resend.com`) instead of an organization account, and has only 17 installs. The official Resend publisher is the `resend` GitHub org (24.2K installs on its top skill). A lookalike name with almost no adoption is a classic impersonation pattern. Installing it could mean running someone else's prompt instructions under the assumption you're getting official Resend guidance.

## How I decided

Three things to check before installing any skill:

1. **Is the publisher verifiable?** Look up the GitHub org or user account directly. Official publishers (like `resend` or `anthropics`) match the company's actual GitHub organization. If the publisher name is a person you've never heard of, check whether they have other repos with real activity. Watch out for domain-style names (`resend.com` instead of `resend`) that try to look official.

2. **How many GitHub stars does the backing repo have?** Skills are just files in a repo. Stars reflect real developer trust over time, not just one-day install spikes. A skill with 400 installs and 362 stars is basically untested. A skill from a repo with 19,000+ stars has had real scrutiny.

3. **Do the install counts match the description's claims?** Legitimate skills grow install counts organically. If a skill claims to be comprehensive and definitive but has fewer installs than simpler competing skills from the same search, something doesn't add up. Trust the crowd count over the marketing copy.
